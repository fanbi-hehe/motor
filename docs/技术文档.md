## 1. 系统概述

### 1.1 功能

对一路直流有刷电机做**闭环速度控制**：

- 用 TIM1 的正交编码器接口读取 400 线 AB 相霍尔编码器，M 法测速得到转速（RPM）；
- 用位置式 PID 计算控制量，输出映射为 TIM2_CH1 的 PWM 占空比与 TB6612 的方向位；
- 用 USART1 把「期望值 / 实际值 / 输出占空比 / 误差」四路数据按 JustFloat 协议送给 VOFA+ 显示波形；
- 通过同一路串口接收 VOFA+ 下发的 ASCII 命令，可在线改目标转速与 PID 参数；
- 用 I2C1 驱动 0.98 寸 OLED 本地显示关键量。

### 1.2 硬件接口分配

| STM32 引脚 | 外设 / 模式 | 连接到 | 说明 |
|---|---|---|---|
| PA0 | TIM2_CH1，PWM 20 kHz | TB6612 **PWMA** | 占空比 0 ~ 4199 |
| PA2 | GPIO 推挽输出 | TB6612 **AIN1** | 方向位 |
| PA3 | GPIO 推挽输出 | TB6612 **AIN2** | 方向位 |
| PA4 | GPIO 推挽输出 | TB6612 **STBY** | 高电平使能驱动器 |
| PE9 | TIM1_CH1，编码器接口 | 编码器 **A 相** | 正交解码 |
| PE11 | TIM1_CH2，编码器接口 | 编码器 **B 相** | 正交解码 |
| PB6 | I2C1_SCL，400 kHz | OLED **SCL** | 7 位地址 0x3C/0x3D |
| PB7 | I2C1_SDA，400 kHz | OLED **SDA** | |
| PA9 | USART1_TX，115200-8-N-1 | USB-TTL **RX** | 发给 VOFA+ |
| PA10 | USART1_RX | USB-TTL **TX** | 接收 VOFA+ 命令 |
| PA13 / PA14 | SWDIO / SWCLK | ST-Link | 下载调试 |

> **晶振必须与 `HSE_VALUE` 一致**（本项目为 8 MHz）。配错会让整棵时钟树按比例缩放：
> 程序照跑，但串口波特率、PWM 频率、控制周期全部失真。详见 [附录 C](#附录-c故障排查)。

`app.c` 是唯一的编排者。

## 2. 数据链路总览

系统一共有 **6 条**独立的数据链路，其中 3 条在中断里、3 条在主循环里：

```
                        ┌──────────────────── 中断上下文 ────────────────────┐
                        │                                                    │
  编码器 A/B ──► TIM1 ──┤─► Encoder_Update() ──► s_rpm                        │
                        │        (链路 B)          │                          │
                        │                          ▼                          │
   目标值 ──────────────┼────────────────► PID_Compute() ──► Motor_SetDuty()  │
   (s_target_rpm)       │                    (链路 C)              │           │
                        │                                          ▼           │
                        │                              TB6612 ──► 电机          │
                        └────────────────────────────────────────────────────┘
                                        ▲                     │
                                        │                     │ (测速反馈闭环)
                                        │                     │
   ┌────────────────────────────────────┴─────────────────────┴──────────────┐
   │                          主循环 (App_Loop)                                │
   │                                                                          │
   │  链路 D  状态 ──► JustFloat 组帧 ──► TX 环 ──► TXE 中断 ──► UART ──► VOFA+ │
   │  链路 E  VOFA+ ──► UART ──► RXNE 中断 ──► RX 环 ──► 行装配 ──► 命令解析    │
   │  链路 F  状态 ──► OLED 显存 ──► 脏页 ──► I2C ──► 屏幕                     │
   └──────────────────────────────────────────────────────────────────────────┘
```

其中 **链路 C 是唯一的闭环**（B→C→电机→B），其余都是单向的观测或控制通道。
链路 A（SysTick）是驱动链路 B/C 的时基。

| 链路 | 起点 | 终点 | 上下文 | 周期 |
|---|---|---|---|---|
| A 时基调度 | SysTick | App_Tick 内的三个节拍 | 中断 | 1 ms |
| B 转速测量 | 编码器脉冲 | `s_speed_rpm` | 中断 | 10 ms |
| C 闭环控制 | `s_target_rpm` | TB6612 PWM | 中断 | 10 ms |
| D 上行遥测 | 状态变量 | VOFA+ 波形 | 主循环 + TX 中断 | 10 ms |
| E 下行命令 | VOFA+ 发送框 | 状态变量 | RX 中断 + 主循环 | 事件驱动 |
| F 本地显示 | 状态变量 | OLED 像素 | 主循环 | 100 ms |

## 3. 链路 A：时基与任务调度

### 3.1 时基来源

SysTick 由 `HAL_Init()` 配置为 **1 ms** 中断一次（`HAL_InitTick(TICK_INT_PRIORITY)`），
中断优先级 **15（最低）**。`SysTick_Handler()` 里先调 `HAL_IncTick()` 维护 HAL 的毫秒计数，
再调用应用层的 `App_Tick()`：

```c
void SysTick_Handler(void)
{
  HAL_IncTick();
  App_Tick();          /* ← 应用层时基，见 stm32f4xx_it.c */
}
```

### 3.2 三个节拍

`App_Tick()` 用私有计数器 `s_ms` 做分频，产生三个节拍：

```c
void App_Tick(void)
{
  s_ms++;
  if ((s_ms % 10u)  == 0u) { App_ControlStep(); }   /* 10 ms  链路 B+C（中断内） */
  if ((s_ms % 10u)  == 0u) { s_tele_due = 1u;     } /* 10 ms  置上报标志（链路 D） */
  if ((s_ms % 100u) == 0u) { s_oled_due = 1u;     } /* 100 ms 置显示标志（链路 F） */
}
```

| 节拍 | 周期 | 频率 | 执行位置 | 对应宏 |
|---|---|---|---|---|
| 控制环 | 10 ms | 100 Hz | **中断内**，立即执行 | `APP_CONTROL_PERIOD_MS` |
| 遥测 | 10 ms | 100 Hz | 主循环，置标志后延后执行 | `APP_TELEMETRY_PERIOD_MS` |
| 显示 | 100 ms | 10 Hz | 主循环，置标志后延后执行 | `APP_OLED_PERIOD_MS` |

**为什么控制环必须在中断里立即执行，而遥测/显示只置标志？**

- 控制环的采样周期直接进入 PID 的 `dt`。如果它放在主循环，OLED 刷新（一次约 25 ms）
  会把周期从 10 ms 拉长到 35 ms，而 PID 仍然按 `dt = 0.01` 计算 ——
  微分项会被放大 3.5 倍，积分项累积量少 3.5 倍，控制器行为完全不可预期。
- 遥测和显示是"尽力而为"的观测通道，晚 20 ms 只是波形上一点点抖动，
  完全可以容忍，因此放主循环，绝不占用中断时间。

### 3.3 主循环

```c
while (1)
{
  App_Loop();      /* 永不返回 */
}
```

```c
void App_Loop(void)
{
  VOFA_Poll(App_OnCommand);        /* 链路 E：解析下行命令           */
  if (s_tele_due) { s_tele_due = 0; App_TelemetryTask(); }  /* 链路 D */
  if (s_oled_due) { s_oled_due = 0; App_DisplayTask();   }  /* 链路 F */
}
```

主循环是**纯轮询 + 标志位**结构，没有阻塞等待、没有 RTOS：
三个任务各自占用主循环的时间，谁也不会饿死（最坏情况是 OLED 刷新占用 25 ms，
期间命令解析推迟，但命令字节仍在 RX 环形缓冲里排队，不会丢）。

## 4. 链路 B：转速测量（编码器 → RPM）

```
 编码器 A 相 ──► PE9  ──┐
                        ├─► TIM1 正交解码 (EncoderMode = TI12) ──► CNT (16 位)
 编码器 B 相 ──► PE11 ──┘                                              │
                                                                       │ 每 10 ms
                                                                       ▼
                                          delta = (int16)(CNT - last)  ──► M 法换算 ──► 一阶低通 ──► s_rpm
```

### 4.1 硬件配置

| 项 | 值 | 位置 |
|---|---|---|
| 定时器 | TIM1（高级定时器，仅用作编码器接口，不输出 PWM） | `tim.c` |
| 编码器模式 | `TIM_ENCODERMODE_TI12`（AB 双方沿计数 = **4 倍频**） | `tim.c:51` |
| 预分频 / 周期 | Prescaler = 0，Period = 65535（16 位满量程） | `tim.c` |
| 输入滤波 | IC1Filter = 0，IC2Filter = 0（不滤波） | `tim.c` |
| 计数方向 | 正转为增，反转（AB 相序反转）为减 | 硬件决定 |

**为什么用 TI12 而不是 TI1？**

| 编码器模式 | 计数边沿 | 倍频 | 400 线编码器分辨率 |
|---|---|---|---|
| TI1 (SMS=001) | 仅 TI1FP1 边沿 | 2× | 800 计数/圈 |
| TI2 (SMS=010) | 仅 TI2FP2 边沿 | 2× | 800 计数/圈 |
| **TI12 (SMS=011)** | **TI1、TI2 双方沿** | **4×** | **1600 计数/圈** |

4 倍频把速度分辨率提高了整整一倍 —— 在 10 ms 窗口下，
分辨率从 7.5 RPM/计数提升到 3.75 RPM/计数，对低速段的控制质量影响明显。

### 4.2 每转计数与分辨率

```
ENCODER_COUNTS_PER_REV = ENCODER_LINES × ENCODER_MULTIPLE × ENCODER_GEAR_RATIO
                       = 400 × 4 × 1
                       = 1600   [计数/圈]
```

**减速比的语义**（`ENCODER_GEAR_RATIO`）：

| 编码器安装位置 | 应填值 | 测出的转速含义 |
|---|---|---|
| 电机轴，输出经 30:1 减速箱 | `30.0f` | 减速箱输出轴转速 |
| 减速箱输出轴 | `1.0f` | 输出轴转速 |
| 电机轴，且只关心电机转速 | `1.0f` | 电机轴转速 |

### 4.3 M 法测速公式

在固定时间窗口 `T = 10 ms` 内数脉冲增量 `ΔN`：

```
              ΔN            60 s/min
    n [RPM] = ────────── × ─────────────
              N_rev           T [min]

其中 N_rev = 1600 计数/圈，T = 10 ms = 1.6667e-4 min
```

代码里预先把系数算成常量，运行时只做一次乘法：

```c
#define ENCODER_MIN_PER_TICK   (ENCODER_SAMPLE_MS / 60000.0f)          /* 1.6667e-4 min */
#define ENCODER_RPM_PER_COUNT  (1.0f / ENCODER_COUNTS_PER_REV \
                                       / ENCODER_MIN_PER_TICK)         /* 3.75 RPM/计数 */

rpm = (float)delta * ENCODER_RPM_PER_COUNT;
```

**换算表（400 线 × 4 倍频，10 ms 窗口）**

| ΔN (计数/10 ms) | 转速 | 说明 |
|---|---|---|
| 1 | 3.75 RPM | **分辨率下限** |
| 80 | 300 RPM | |
| 133 | 500 RPM | 本系统上电默认目标 |
| 267 | 1000 RPM | 仿真模型中的典型工作点 |
| 320 | 1200 RPM | 该电机的满占空比转速（模型假设） |

### 4.4 16 位计数器回绕处理

TIM1 是 16 位计数器，从 65535 回到 0（或反过来）时直接相减会得到 ±65535 的错误值。
这里用**有符号 16 位语义**做差，让回绕自动正确：

```c
cur   = (int32_t)__HAL_TIM_GET_COUNTER(&htim1);
delta = (int32_t)(int16_t)((uint16_t)cur - (uint16_t)s_last_cnt);
s_last_cnt = cur;
```

原理：无符号相减在模 2¹⁶ 下得到正确的"环形距离"，
再按有符号 16 位解释，就把"绕过大半圈"解释成"反向走了小半圈"。

**适用边界**：只要单个采样窗口内 |ΔN| < 32768 就绝对安全。

```
最大可测转速 = 32767 计数 / 10 ms × 3.75 RPM/计数 = 122 876 RPM
```

任何真实的 400 线减速电机都远低于此（典型 100~3000 RPM），因此不存在回绕歧义。

### 4.5 一阶低通滤波

M 法测速的输出是**量化**的（3.75 RPM 一跳），并且带有齿轮啮合、霍尔器件抖动引起的齿槽脉动。
这些高频成分会被 PID 的微分项放大，所以先做一阶低通（EMA）：

```
    n_f[k] = n_f[k-1] + α · ( n_raw[k] − n_f[k-1] )        α = ENCODER_FILTER_ALPHA = 0.40
```

| α | 效果 | 等效 −3 dB 带宽 | 群延迟 |
|---|---|---|---|
| 1.0 | 不滤波，最跟手，噪声最大 | — | 0 |
| **0.40（默认）** | **平衡** | **≈ 8.3 Hz** | **≈ 15 ms + 5 ms（窗口均值）** |
| 0.10 | 很平滑，但响应明显变迟钝 | ≈ 1.7 Hz | ≈ 90 ms |

带宽与群延迟由 EMA 的频响精确算出（`T = 10 ms`）：

```
|H(e^{jωT})|² = α² / [ 1 − 2(1−α)cos(ωT) + (1−α)² ] = 1/2
α=0.40 → cos(ω_c T) = 0.8667 → ω_c T = 0.5236 rad → f_c = 8.33 Hz
群延迟 ≈ (1−α)/α · T = 0.6/0.4 × 10 ms = 15 ms
```

> **注意**：滤波是在 PID **之前**做的，所以它引入的 15 ms 延迟**直接进入控制回路**，
> 会限制可用的最大比例增益。这是"测速平滑度"与"控制带宽"之间的必然取舍，
> 详见 [13.3 反馈延迟预算](#133-反馈延迟预算)。

### 4.6 方向取反

如果电机正转时读数却是负的（编码器 AB 相接反、或电机线接反），
把 `ENCODER_DIR_INVERT` 改成 `1`，或在硬件上对调 A/B 相：

```c
#if (ENCODER_DIR_INVERT != 0)
  delta = -delta;
#endif
```

> 极性接反本身不会让电机不转，但会让闭环变成**正反馈**：
> PID 发现"转速总是不够"，于是加大输出，电机更快，读数更负，误差更大……直到输出饱和。
> 固件的过速保护专门抓这种情况，见 [第 10 章](#10-保护与故障处理)。

## 5. 链路 C：闭环控制（目标 → PID → 占空比）

```
                                              ┌──────────── 每 10 ms (中断内) ────────────┐
                                              │                                          │
  s_target_rpm ──┐                            ▼                                          │
  (命令 / 默认值) │              ┌──────────────────────┐                                │
                 ├─────────────►│     PID_Compute()    │──► u [−4199, +4199] ──┐        │
                 │   e = t − y  │  ┌────────────────┐  │                       │        │
                 │              │  │ P: Kp·e        │  │                       ▼        │
                 │              │  │ I: ∫Ki·e dt    │  │            ┌──────────────────┐ │
                 │              │  │ D: −Kd·dy/dt   │  │            │  Motor_SetDuty() │ │
                 │              │  └────────────────┘  │            │  方向 + 占空比    │ │
                 │              │  抗饱和 / 积分分离   │            └────────┬─────────┘ │
                 │              └──────────────────────┘                     │           │
                 │                       ▲                                   ▼           │
                 │                       │                          TB6612 ──► 电机      │
                 │                       │                                   │           │
                 │                  s_speed_rpm ◄── 编码器 ◄─────────────────┘           │
                 └───────────────────────┴───────────────────────────────────────────────┘
                                     (链路 B 提供反馈)
```

### 5.1 控制步进函数

```c
static void App_ControlStep(void)          /* 每 10 ms，在 SysTick 中断里调用 */
{
  float out;

  Encoder_Update();                        /* ① 链路 B：更新 s_speed_rpm            */
  s_speed_rpm = Encoder_GetSpeedRPM();

  /* ② 通信超时保护（可选，默认关闭） */
  if ((s_safe_ms > 0u) && (s_enabled != 0u) && timeout) { ... 停机 ... }

  /* ③ 保护锁定：停机直到被 START/RESET/新目标解除 */
  if (s_fault != 0u) { Motor_Stop(); return; }

  /* ④ 未使能：停机并复位控制器，误差清零 */
  if (s_enabled == 0u) { Motor_Stop(); PID_Reset(&s_pid); s_err = 0.0f; return; }

  /* ⑤ 闭环 / 开环 */
  if (s_closed_loop != 0u)
  {
    out    = PID_Compute(&s_pid, s_target_rpm, s_speed_rpm, 0.01f);   /* ← 核心 */
    s_err  = s_pid.err;
    Motor_SetDuty((int16_t)out);
  }
  else
  {
    s_err = s_target_rpm - s_speed_rpm;
    Motor_SetDuty(s_open_duty);                                       /* 开环直通 */
  }

  /* ⑥ 保护检查（过速 / 反馈丢失） */
  App_FaultCheck();
}
```

执行顺序很重要：**先测速 → 再算 PID → 再输出 → 最后查保护**，
保证同一个控制周期内用的是同一份反馈数据。

### 5.2 输出映射到 TB6612

`Motor_SetDuty(int16_t duty)` 把带符号的 PID 输出翻译成"方向位 + PWM 比较值"：

| PID 输出 u | AIN1 | AIN2 | TIM2_CCR1 | 电机状态 |
|---|---|---|---|---|
| `u > 0` | 1 | 0 | `u` | 正转 |
| `u < 0` | 0 | 1 | `-u` | 反转 |
| `u = 0` | 0 | 0 | 0 | 自由滑行（输出高阻） |

```c
__HAL_TIM_SET_COMPARE(&htim2, MOTOR_PWM_CHANNEL, pwm);
```

占空比换算：

```
                      CCR1             CCR1
    占空比 D = ───────────────── = ──────────
                ARR + 1              4200

    CCR1 = 4199 → D = 99.98%  ≈ 满占空比
    CCR1 = 2100 → D = 50%
    CCR1 =  210 → D =  5%
```

> 注意 `Motor_SetDuty(0)` 是**滑行停止**（两方向位都为 0，电机两端悬空）；
> 另外提供了 `Motor_Brake()`（AIN1=AIN2=1，绕组短接制动），PID 正常停机时不用它，
> 因为频繁制动会造成电流冲击。

### 5.3 PWM 频率

```
    TIM2 挂在 APB1 上，APB1 分频系数为 4（≠1），因此定时器时钟 = PCLK1 × 2

    TIM2_CLK = 42 MHz × 2 = 84 MHz
    f_PWM    = TIM2_CLK / [(PSC+1) × (ARR+1)]
             = 84 MHz / [1 × 4200]
             = 20 kHz
```

> 这是 STM32 时钟树的一个经典陷阱：**APB 分频系数不为 1 时，定时器时钟是 PCLK 的两倍**。
> 若误按 168 MHz 计算会得到 40 kHz 的错误结果。

选择 20 kHz 的理由：

- 高于人耳上限（20 kHz），电机不会发出讨厌的啸叫；
- 低于 TB6612 的推荐上限（100 kHz），开关损耗可控；
- 相对电机电气时间常数（约 1 ms）足够高，电流纹波小。

`AutoReloadPreload = ENABLE` 保证改 CCR 时不会产生毛刺。

### 5.4 使能与模式

| 状态位 | 含义 | 由谁改变 |
|---|---|---|
| `s_enabled` | 驱动总使能 | 上电自动（`APP_AUTO_START`）、`TARGET`/数字/`DUTY` 自动置 1、`START` 置 1、`STOP`/保护置 0 |
| `s_closed_loop` | 1 = 闭环，0 = 开环 | `OPEN` / `CLOSE` / `DUTY` |
| `s_fault` | 保护锁定 | `App_FaultCheck()` 置 1；`START`/`RESET`/`TARGET` 清 0 |

**设计取向**：`TARGET <rpm>` 和直接发数字会**自动使能驱动**。
"设定目标转速"本身就表达了"我想让它转"的意图，再要求一条额外的 `START`
只会让人以为命令没生效 —— 这是本项目实际踩过的坑。

### 6.1 通道定义

| 通道 | 变量 | 单位 | 说明 |
|---|---|---|---|
| ch0 | `s_target_rpm` | RPM | 期望值（VOFA+ 里应看到阶跃方波） |
| ch1 | `s_speed_rpm` | RPM | 实际值（应跟随 ch0） |
| ch2 | `Motor_GetDuty()` | PWM 计数 | 控制器输出，±4199，可看积分饱和 |
| ch3 | `s_err` | RPM | 误差，等于 `ch0 − ch1`（使能时） |

### 6.2 JustFloat 帧格式

VOFA+ JustFloat 是**纯二进制小端浮点流**，帧内不带通道数，靠帧尾切分：

```c
struct Frame {
    float         ch_data[4];                    /* 4 × 4 = 16 字节，小端 */
    unsigned char tail[4] = {0x00, 0x00, 0x80, 0x7f};   /* 帧尾 */
};                                               /* 一帧固定 20 字节 */
```

帧尾 `00 00 80 7F` 按小端解释就是浮点 **+Inf**（位型 `0x7F800000`），
这是协议约定的"帧结束标记"。

**构造实现**（`vofa.h`，纯函数、无硬件依赖，因此可做主机端单元测试）：

```c
static inline uint16_t VOFA_BuildJustFloat(uint8_t *out, const float *v, uint8_t n)
{
  uint16_t idx = 0u;  uint8_t i;  uint32_t raw;

  for (i = 0u; i < n; i++)
  {
    memcpy(&raw, &v[i], sizeof(raw));        /* 取位模式，避免联合体双关 */
    out[idx++] = (uint8_t)(raw & 0xFFu);     /* 显式小端展开，与主机字节序无关 */
    out[idx++] = (uint8_t)((raw >> 8)  & 0xFFu);
    out[idx++] = (uint8_t)((raw >> 16) & 0xFFu);
    out[idx++] = (uint8_t)((raw >> 24) & 0xFFu);
  }
  out[idx++] = 0x00u; out[idx++] = 0x00u;
  out[idx++] = 0x80u; out[idx++] = 0x7Fu;
  return idx;
}
```

**字节序示例**（单元测试逐字节核对过）：

| 浮点值 | IEEE-754 位型 | 线上字节 |
|---|---|---|
| `1.0f` | `0x3F800000` | `00 00 80 3F` |
| `100.5f` | `0x42C90000` | `00 00 C9 42` |
| `-2.5f` | `0xC0200000` | `00 00 20 C0` |
| `-0.125f` | `0xBE000000` | `00 00 00 BE` |

一帧完整数据（4 通道）在电机静止时是：

```
00 00 00 00 | 00 00 00 00 | 00 00 00 00 | 00 00 00 00 | 00 00 80 7F
   ch0=0        ch1=0        ch2=0         ch3=0         帧尾
```

> **上位机必须把通道数设为 4**。这是 JustFloat 最常见的坑：帧里没有通道数字段，
> 上位机纯靠用户配置的通道数去切分，设错了就是一堆看似随机的曲线。

### 6.3 为什么不用阻塞式发送

最初版本用 `HAL_UART_Transmit()`（阻塞）在主循环里发帧。它的吞吐足够
（20 字节 @115200 ≈ 1.74 ms），但**与 OLED 刷新串行**：

```
主循环时间轴（旧方案）:
  |─发帧 1.74ms─|─发帧 1.74ms─|─────── OLED 全屏刷新 25ms ───────|─发帧─|...
                                                                  ↑
                                        这段时间里 10ms 节拍到了 2~3 次，
                                        但主循环被 I2C 阻塞，帧发不出去 → 丢帧 + 抖动
```

改成**中断 + 环形缓冲**后，`VOFA_SendSamples()` 只做一次 `memcpy`（约 1 µs）就返回，
由 TXE 中断在后台逐字节搬运。主循环被 I2C 卡住多久都不影响发送节奏：

```
TXE 中断: 每 86.8 µs 触发一次（115200 baud），每次搬 1 字节 → 20 字节/帧用 1.74 ms 发出
主循环:   往环里塞一帧就完事，塞完立刻去刷 OLED
```

### 6.4 TX 环形缓冲与临界区

```c
static volatile uint8_t  s_txring[512];   /* 512 B ≈ 25 帧 JustFloat */
static volatile uint16_t s_tx_head;       /* 仅中断读 */
static volatile uint16_t s_tx_tail;       /* 仅主循环写 */
```

这是标准的**单生产者-单消费者（SPSC）环形缓冲**：写指针只由主循环动，
读指针只由中断动，因此不需要互斥锁。

但"写入 + 使能 TXE 中断"这一段必须用 `PRIMASK` 保护，否则会与中断里
"缓冲区空了就关中断"撞车而**永久丢失一个字节**：

```
危险时序（无保护）：
  主循环: 写入字节 →（被中断打断）
  中断:   取走最后一字节 → 发现环空 → 关 TXE 中断
  主循环: 恢复 → 使能 TXE 中断 …… 已经晚了，字节留在环里再也没人取

正确做法：
  PRIMASK = 0 的临界区里完成"写入 + 使能中断"，
  中断要么完全发生在之前（使能生效），要么完全之后（中断自己会看到新数据）
```

```c
static void VOFA_TxPush(const uint8_t *p, uint16_t len)
{
  uint32_t primask = __get_PRIMASK();
  __disable_irq();

  if (len > 剩余空间) { __set_PRIMASK(primask); return; }   /* 整帧丢弃，绝不发半帧 */
  ... 逐字节写入 ...
  __HAL_UART_ENABLE_IT(&huart1, UART_IT_TXE);

  __set_PRIMASK(primask);
}
```

**为什么空间不够时要整帧丢弃？**
JustFloat 靠帧尾切帧，发半帧会让上位机一直等不到帧尾，把后续数据全部错位。
丢一整帧只是波形少一个点，危害小得多。

### 6.5 带宽核算

| 数据格式 | 单帧字节 | 100 Hz 时带宽 | 115200 链路占用 |
|---|---|---|---|
| **JustFloat（当前）** | 20 | 2 000 B/s | **17.4%** |
| FireWater（可选） | 30（4 通道实测） | 3 000 B/s | 26.0% |

链路余量充足，理论上 JustFloat 可支持到 500 Hz 上报（仍只占 87%）。
当前取 100 Hz 是为了与 10 ms 控制节拍对齐。

### 6.6 文本回显为什么要静音

JustFloat 是纯二进制流，任何 ASCII 文本（`HELP` / `SAVE` 的输出）
都会滞留在上位机缓冲区里，直到下一个帧尾到达时被**当成一大帧垃圾数据**解析
（官方文档也提示这会让缓冲区爆满甚至卡死）。

因此：

```c
#if (VOFA_USE_JUSTFLOAT != 0)
#define VOFA_TEXT_REPLY_DEFAULT 0u    /* JustFloat：默认静音 */
#else
#define VOFA_TEXT_REPLY_DEFAULT 1u    /* FireWater：默认打开 */
#endif
```

需要看 `HELP` / `SAVE` 时，先发一次 `TEXT 1`，调完再 `TEXT 0`。
`TEXT` 命令本身**强制回显**（先打开再打印再应用新状态），
保证"关闭"这个动作也有确认信息。

### 6.7 备用：FireWater 文本帧

把 `vofa.h` 里的 `VOFA_USE_JUSTFLOAT` 改成 `0` 即可切回 ASCII 文本帧，
协议为 CSV 风格、以换行结束：

```
"ch0,ch1,ch2,ch3\n"     例如:  1500.00,1489.34,3821.00,-10.66
```

两种帧的构造函数都是 `vofa.h` 里的 `static inline` 纯函数，都有单元测试覆盖。

### 7.1 接收中断

```c
void USART1_IRQHandler(void) { VOFA_IrqHandler(); }
```

```c
void VOFA_IrqHandler(void)
{
  uint32_t sr = USART1->SR;                 /* 只读一次，保证整段判断基于同一时刻 */

  if (sr & USART_SR_RXNE) {
    VOFA_RxByte((uint8_t)(USART1->DR & 0xFFu));   /* 读 DR 同时清 RXNE 与 ORE */
  } else if (sr & (ORE | NE | FE | PE)) {
    (void)USART1->DR;                             /* 错误标志必须先读 SR 再读 DR 才能清 */
  }

  if (sr & USART_SR_TXE) { /* 见 6.4：从 TX 环取字节写 DR，环空则关 TXE 中断 */ }
}
```

**收发都不经过 HAL 的状态机**（不用 `HAL_UART_Receive_IT` / `HAL_UART_Transmit_IT`），
直接操作寄存器。原因：HAL 的 UART 收发共用 `gState` 状态机，
一边阻塞发送一边中断接收很容易互相干扰；自己管理收发环反而更简单、更确定。

`ORE`（溢出）必须处理：它不像 RXNE 那样读一次 DR 就消失，
如果不清会**反复进入中断**把 CPU 占满。

### 7.2 行装配与空闲成行

主循环里 `VOFA_Poll()` 把环形缓冲的字节逐个取出：

```c
if (c == '\n' || c == '\r')   → 一行结束，dispatch
else if (行缓冲没满)           → 追加到 s_line
else                          → 行缓冲溢出，丢弃这一行重新同步
```

**兼容不发送换行的串口工具**：如果收到字节后 40 ms 内没有新字节，
就把当前缓冲当作一整行处理：

```c
if (!got && (s_line_len > 0) && (HAL_GetTick() - s_last_rx_tick > 40)) dispatch();
```

这样无论用户在 VOFA+ 里勾没勾"追加换行"都能正常识别。

### 7.3 命令解析

解析分两层：

**① 纯数字快速通道** —— 整行只由 `[0-9+-. ]` 组成就直接当目标转速。
这是最常用的操作（在 VOFA+ 发送框敲 `1500` 回车），不需要任何前缀。

**② 关键字命令** —— `App_MatchWord()` 做**不区分大小写**的整词匹配，
并要求关键字后面是 `\0` / 空格 / Tab / `=` / `:`，避免 `KI` 误匹配 `KILL`：

```c
static uint8_t App_MatchWord(const char *s, const char *word, const char **rest)
{
  while (*word) {                       /* 逐字符比较，统一转大写 */
    char a = *s, b = *word;
    if (a >= 'a' && a <= 'z') a -= 32;
    if (b >= 'a' && b <= 'z') b -= 32;
    if (a != b) return 0u;
    s++; word++;
  }
  /* 后面必须紧跟分隔符，否则不是整词 */
  if (*s && *s != ' ' && *s != '\t' && *s != '=' && *s != ':') return 0u;
  while (*s == ' ' || *s == '\t' || *s == '=' || *s == ':') s++;
  *rest = s;                            /* 剩余部分就是参数 */
  return 1u;
}
```

参数解析用手写的 `App_ParseFloat()`（支持符号、整数、小数），
**故意不用 `sscanf`**：newlib-nano 下浮点 scanf 会显著增大固件。

## 8. 链路 F：本地显示（状态 → 显存 → I2C → OLED）

```
 状态变量 ──► OLED_DrawXxx() ──► s_fb[8][128] 显存 ──► 标记脏页 s_dirty[page]
                                        │
                                        ▼  OLED_Refresh()
                            只把脏页通过 I2C 推出去（每页 129 字节）
                                        │
                                        ▼
                         SSD1306 128×64 ──► 屏幕
```

### 8.1 显存组织

SSD1306 的显存是**按页（page）组织**的，每页 8 行像素、128 列：

```
  s_fb[page][x] 的 bit0 = 该页最上面一行像素，bit7 = 最下面一行

  page 0 : y = 0..7      ┌────────────────────────────┐
  page 1 : y = 8..15     │  128 列                    │
  page 2 : y = 16..23    │  每列 1 字节 = 8 个像素     │
  ...                    └────────────────────────────┘
  page 7 : y = 56..63
```

绘制操作最终都落到一个像素级函数：

```c
void OLED_DrawPixel(uint8_t x, uint8_t y, uint8_t on)
{
  uint8_t page = y >> 3;
  uint8_t mask = 1u << (y & 7u);
  if (on) s_fb[page][x] |=  mask;
  else    s_fb[page][x] &= ~mask;
  s_dirty[page] = 1u;                       /* 标脏 */
}
```

### 8.2 脏页刷新

**这是本链路的关键优化。** 全屏 128×64 = 1024 字节，在 400 kHz I2C 下：

```
  一页 = 1 控制字节 + 128 数据字节 = 129 B
  线上时间 = 129 B × 9 bit/B ÷ 400 kHz ≈ 2.9 ms
  全屏 8 页 ≈ 23 ms（外加寻址命令约 2 ms）
```

如果每 100 ms 都无脑全屏推送，主循环有 **25% 的时间被 I2C 阻塞**。
所以只推送 `s_dirty[page] != 0` 的页，并遵循两条规则：

- **绘制只改显存、标脏**，不做 I2C；
- **`OLED_Refresh()` 只发脏页**，发成功才清脏标记，失败保留脏标记下次重试。

配合 `OLED_DrawStringPad(x, y, str, chars)`（先擦满 `chars` 格再画字符串），
每行都是定宽覆盖写，不会留下上一次更长字符串的残影。

### 8.3 字库与放大

内置 6×8 ASCII 点阵（`oled_font.h`，95 个字符）：
每个字符 6 列，每列 1 字节，**bit0 在上**，第 6 列留作字间距。

`OLED_DrawStringScaled(x, y, str, scale)` 支持任意整数放大：
`scale=1` 是 6×8，`scale=2` 是 12×16。实现就是把每个点铺成 `scale × scale` 的方块。

### 8.4 128×64 屏幕布局

```
┌────────────────────────────────────────────┐
│ ┌──────────┐                               │  y=0..15
│ │  500     │  ← 12×16 大字：目标转速  SET rpm│
│ └──────────┘                               │
│ ┌──────────┐                               │  y=16..31
│ │  498     │  ← 12×16 大字：实际转速  ACT rpm│
│ └──────────┘                               │
│ ERR  -2        OUT  1840  SAT              │  y=32..39
│ P2.00    I10.000    D0.0200                │  y=40..47

```

| 行 | 内容 | 说明 |
|---|---|---|
| 0–15 | 目标转速 | 12×16 大字 |
| 16–31 | 实际转速 | 12×16 大字 |

### 8.5 健壮性

- **屏幕可选**：`OLED_Init()` 先探测 0x3C，不通再试 0x3D；
  都失败就返回 0，后续绘制静默丢弃，**完全不影响电机控制**。
- **总线自恢复**：I2C 连续 3 次发送失败就 `HAL_I2C_DeInit()` + `MX_I2C1_Init()`，
  处理从机把 SDA 拉死的情况。
- **SH1106 兼容**：`OLED_CTRL_SH1106 = 1` 时改走 SH1106 的页寻址命令
  （它不支持 SSD1306 的 `0x20/0x21/0x22`），供 1.3 寸屏使用。

## 9. PID 控制器详解

这是整套系统里最需要讲清楚的部分。本章按
**连续形式 → 离散实现 → 每一项的作用 → 三个"工程补丁" → 整定方法** 的顺序展开。

### 9.1 连续形式与"理想 PID"的问题

教科书上的理想位置式 PID：

```
              ┌            1   t            d        ┐
   u(t) = Kp ·│ e(t) + ──── ∫ e(τ)dτ + Td ── e(t)   │
              └        Ti   0             dt       ┘
```

直接把它离散化照搬到电机速度环上会立刻遇到三个问题：

| 问题 | 现象 | 本实现的对策 |
|---|---|---|
| **微分冲击** | 设定值阶跃时 `de/dt` 是冲激，输出瞬间打满，电流冲击大 | **微分先行**：只对测量值求导（9.4） |
| **积分饱和** | 启动阶段误差大，积分一路累积，退饱和时严重超调 | **条件积分抗饱和**（9.7）+ **积分分离**（9.6） |
| **噪声放大** | 编码器量化噪声被 Kd 成倍放大，电机抖动、发热 | **微分低通**（9.5） |

### 9.2 本实现的完整公式

**符号定义**

| 符号 | 含义 | 单位 |
|---|---|---|
| `r[k]` | 目标转速 `s_target_rpm` | RPM |
| `y[k]` | 实测转速 `s_speed_rpm`（已低通） | RPM |
| `e[k]` | 误差 `r[k] − y[k]` | RPM |
| `T` | 控制周期，**10 ms** | s |
| `u[k]` | 控制器输出（占空比计数） | counts，±4199 |

**计算步骤（`PID_Compute()`，每个控制周期执行一次）**

```
① 误差
      e[k] = r[k] − y[k]

② 测量值变化率（微分先行）
      ẏ_raw[k] = ( y[k] − y[k−1] ) / T

③ 微分项一阶低通
      ẏ_f[k] = ẏ_f[k−1] + α · ( ẏ_raw[k] − ẏ_f[k−1] )          α = 0.30

④ 积分项（含积分分离与限幅）
      if ( |e[k]| ≤ e_sep  或  e_sep ≤ 0 ) ：
          I_cand = clamp( I[k−1] + Ki · e[k] · T ,  ±I_lim )
      else：
          I_cand = I[k−1]

⑤ 三项求和
      P = Kp · e[k]
      D = Kd · ẏ_f[k]
      u_raw = P + I_cand − D

⑥ 条件积分抗饱和（关键）
      if ( u_raw >  +U_lim  且  e[k] > 0 )  或
         ( u_raw <  −U_lim  且  e[k] < 0 )：
              I_cand = I[k−1]                ← 冻结积分
              u_raw  = P + I_cand − D        ← 用冻结值重算

      I[k] = I_cand

⑦ 输出限幅
      u[k] = clamp( u_raw , ±U_lim )
```

**对应代码**（`pid.c:62-131`）：

```c
err = target - measure;

/* 微分先行 + 低通 */
d_raw = (measure - pid->last_measure) / dt;
pid->last_measure = measure;
pid->d_filtered += pid->d_lpf_alpha * (d_raw - pid->d_filtered);

/* 积分分离 + 限幅 */
i_cand = pid->integral;
if ((pid->sep_zone <= 0.0f) || (PID_Abs(err) <= pid->sep_zone)) {
    i_cand += pid->Ki * err * dt;
    i_cand  = PID_Clamp(i_cand, pid->integral_limit);
}

/* 三项 */
p_term = pid->Kp * err;
d_term = pid->Kd * pid->d_filtered;
out    = p_term + i_cand - d_term;

/* 条件积分抗饱和 */
sat_hi = (out >  pid->output_limit);
sat_lo = (out < -pid->output_limit);
if ((sat_hi && err > 0.0f) || (sat_lo && err < 0.0f)) {
    i_cand = pid->integral;                 /* 冻结 */
    out    = p_term + i_cand - d_term;      /* 重算 */
}
pid->integral = i_cand;

/* 输出限幅 */
if (out >  pid->output_limit) out =  pid->output_limit;
if (out < -pid->output_limit) out = -pid->output_limit;
```

### 9.3 各分量的物理意义与量纲

| 分量 | 表达式 | 量纲 | 数值直觉（默认参数） |
|---|---|---|---|
| **P** | `Kp · e` | counts | `Kp=2.0`，误差 100 RPM → **200 counts**（4.8% 占空比） |
| **I** | `∫ Ki·e dt` | counts | `Ki=10`，误差 100 RPM，每周期累加 `10×100×0.01 = 10` counts，即 **1000 counts/s** |
| **D** | `−Kd · dy/dt` | counts | `Kd=0.02`，转速上升率 1000 RPM/s → **20 counts** 的制动量 |

**为什么"P 单独作用会有静差"**

假设电机增益 `K_plant = 1200 RPM / 4199 counts = 0.2858 RPM/count`（满占空比 1200 转）。
只开 P：

```
    y = K_plant · u = K_plant · Kp · e = K_plant · Kp · (r − y)

               K_plant · Kp              0.2858 × 2
    y = r · ────────────────── = r · ───────────────── = 0.3637 · r
              1 + K_plant · Kp          1 + 0.5716
```

即目标 1000 RPM 时只能到 **364 RPM**，静差 636 RPM。
必须靠积分项把剩余占空比补上 —— 这就是 I 项存在的唯一理由。

### 9.4 微分先行（Derivative on Measurement）

**问题**：标准 PID 的 D 项是 `Kd · de/dt`，而 `e = r − y`。
当 `r` 发生阶跃（比如发 `TARGET 1000`），`de/dt` 理论上是一个冲激函数，
D 项瞬间输出一个巨大的尖峰 → PWM 打满 → 电流冲击、机械冲击。

**做法**：只对**测量值** `y` 求导，不对误差 `e` 求导。

```
   标准:   D = Kd · d(r − y)/dt   ← r 的跳变会进 D
   本实现: D = Kd · dy/dt          ← r 怎么跳都不影响 D
```

数学上，因为 `dy/dt = −de/dt + dr/dt`，所以在 `r` 恒定时两者等价；
只有在 `r` 突变的瞬间才有区别 —— 而那个区别正是我们要消除的冲击。

**单元测试验证**：

```
  目标从 0 跳到 5000 RPM，测量值恒为 0
  → 标准 PID 的 D 项会是巨大尖峰
  → 本实现的 d_term == 0.000000   ✅
```

代码里可以看到，`d_raw` 只由 `measure` 构成，`target` 根本没参与：

```c
d_raw = (measure - pid->last_measure) / dt;
```

### 9.5 微分低通滤波

**问题**：编码器是量化的，最小刻度 3.75 RPM。一阶差分后：

```
   Δy = 3.75 RPM（一个量化台阶），T = 0.01 s
   ẏ = 3.75 / 0.01 = 375 RPM/s
   D = Kd · ẏ = 0.02 × 375 = 7.5 counts    ← Kd=0.02 时还可接受
                 = 1.00 × 375 = 375 counts ← Kd 调到 1.0 就是灾难
```

量化噪声在每周期里随机跳 ±1 个台阶，D 项就会在 ±375 counts 之间抖动，
直接表现为电机嗡嗡响、发热。

**做法**：对变化率再做一次一阶低通（EMA）：

```
   ẏ_f[k] = ẏ_f[k−1] + α · ( ẏ_raw[k] − ẏ_f[k−1] )        α = APP_DEFAULT_D_ALPHA = 0.30
```

| α | 等效 −3 dB 带宽（T=10 ms） | 效果 |
|---|---|---|
| 1.0 | — | 不滤波（`PID_Init` 的默认值） |
| **0.30（应用层默认）** | **≈ 5.7 Hz** | 明显抑制量化噪声 |
| 0.10 | ≈ 1.7 Hz | 非常平滑，但 D 项响应也变慢 |

带宽由 EMA 频响算出：

```
α² / [1 − 2(1−α)cos(ωT) + (1−α)²] = 1/2，α=0.30
→ cos(ω_c T) = 0.9357 → ω_c T = 0.3599 rad → f_c = 5.73 Hz
```

**注意**：`PID_Init()` 里 `d_lpf_alpha` 默认是 `1.0`（不滤波），
应用层通过 `PID_SetDerivativeFilter(&s_pid, APP_DEFAULT_D_ALPHA)` 显式设成 0.30。
这样 PID 模块本身保持中立，滤波器是个可选项。

**单元测试验证**：

```
  α = 0.5，测量值从 0 跳到 100 RPM（原始变化率 10000 RPM/s）
  → 滤波后变化率 = 0.5 × 10000 = 5000 RPM/s，Kd=1 → d_term = 5000   ✅
```

### 9.6 积分分离（Integral Separation）

**问题**：启动或大幅变速时误差很大（几百 RPM），
如果此时照常积分，积分项会迅速累积到限幅值，造成大超调和长时间振荡。

**做法**：设一个阈值 `e_sep`（`SEP` 命令 / `APP_DEFAULT_SEP_ZONE`），
**只有误差落进 ±e_sep 区间内才积分**：

```c
if ((pid->sep_zone <= 0.0f) || (PID_Abs(err) <= pid->sep_zone)) {
    i_cand += pid->Ki * err * dt;      /* 只有这里才累积 */
}
```

`sep_zone <= 0` 表示**不启用**（本项目的默认值）。

| 场景 | 建议 |
|---|---|
| 电机响应快、超调小 | `SEP 0`（不启用），让积分全程工作，静差消除最快 |
| 启动/变速超调明显 | `SEP 50~100`，误差大时不积分，接近目标再补 |
| 大幅阶跃频繁 | 启用分离效果明显 |

**单元测试验证**：

```
  sep_zone = 50，err = 100 → 不积分，integral 保持 0        ✅
  sep_zone = 50，err =  20 → 正常积分，integral = 0.2       ✅
```

### 9.7 条件积分抗饱和（Conditional Integration）★

**这是整份文档里最值得讲清楚的一段。**

**问题：积分饱和（Integral Windup）**

考虑上电瞬间：目标 500 RPM，实际 0 RPM，误差 500 RPM。
P 项给出 `2 × 500 = 1000` counts，但电机从静止到 500 转需要约 0.3 s。
在这 0.3 s 里，积分项每 10 ms 累加 `Ki · e · T = 10 × 500 × 0.01 = 50` counts，
30 个周期就累积了 **1500 counts**。而此时 P 项只有几百，输出早就饱和在 4199 了。

等到转速接近目标、误差变小、输出退出饱和时，**积分项还挂着一大坨历史值**
（典型几千 counts），它会继续把输出顶在饱和区 → 转速冲到 900、1000 RPM，
要等误差变负并持续很久才能把积分"拉回来" → **严重超调 + 长时间振荡**。

**做法：条件积分**

```
   输出饱和 且 误差还在把输出往饱和方向推  →  冻结积分（不接受本周期的累加）
```

```c
sat_hi = (out >  pid->output_limit);
sat_lo = (out < -pid->output_limit);

if ((sat_hi && err > 0.0f) || (sat_lo && err < 0.0f)) {
    i_cand = pid->integral;            /* 退回上一周期的积分值 = 冻结 */
    out    = p_term + i_cand - d_term; /* 必须重算，否则 out 还是旧值 */
}
```

两个条件缺一不可：
- **必须饱和** —— 没饱和时积分正常工作，否则永远消不掉静差；
- **必须同向** —— 如果误差已经反向（比如超调了，`err < 0` 而输出还在正向饱和），
  积分**必须被允许往回走**，否则退不出饱和。

第 104 行的判断正是这个逻辑：`sat_hi && err > 0` 是"正向饱和且误差还在要求更大输出"，
此时冻结；`sat_lo && err < 0` 对称。

**定量对比（单元测试用例）**

```
  条件：Kp=0, Ki=1, e≡1000 RPM, T=0.01 s, U_lim=100 counts, I_lim=1e6（不限）
  运行：1000 个周期（10 s）

  无抗饱和： I = Ki·e·T·N = 1 × 1000 × 0.01 × 1000 = 10000 counts   ← 严重饱和
  有抗饱和： I 涨到 U_lim = 100 就冻结，之后不再增长                 ✅
```

更关键的是**退饱和速度**：

```
  紧接着把误差反向（e = −1000 RPM），检查一个周期后：

  有抗饱和： I = 100 + 1×(−1000)×0.01 = 90         ← 立刻开始回落   ✅
             输出 = 90，已经低于饱和限幅 100
  无抗饱和： I = 10000 − 10 = 9990，输出仍被限在 ±100，长时间动弹不得
```

**四种常见的抗饱和做法对比**

| 方法 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **条件积分（本实现）** | 饱和且同向时冻结积分 | 简单、无需额外参数、鲁棒 | 不估计"需要多少积分"，退饱和稍慢 |
| 积分限幅 | 直接 clamp 积分项 | 最简单 | 限幅值难定：太小消不掉静差，太大不解决问题 |
| 反算法（Back-calculation） | `I += Kt·(u_sat − u_raw)·T` | 退饱和最快 | 需要额外整定 `Kt` |
| 积分分离 | 误差大时不积分 | 抑制启动超调 | 只针对"误差大"，不针对"输出饱和" |

**本实现同时用了积分限幅 + 条件积分**：
`I_lim = 4199`（= 满量程）负责兜底，条件积分负责动态行为。
两者配合：任何情况下积分都不会超过满占空比，而饱和时又不会继续累积。

### 9.8 输出限幅与饱和标志

```c
if (out >  pid->output_limit) out =  pid->output_limit;
if (out < -pid->output_limit) out = -pid->output_limit;

pid->saturated = (out >= pid->output_limit) || (out <= -pid->output_limit);
```

`output_limit` 在应用层初始化为 `MOTOR_PWM_MAX = 4199`，即满占空比。
它的另一个用途是**限流**：电源或电机较小时，用 `LIMIT 2000` 把最大占空比压下来。

`saturated` 会被送到 OLED 上显示成 `SAT`，是判断"参数是否已经顶到极限"的直接依据：

- 波形上 `OUT` 长期贴着 ±4199 且转速上不去 → 功率不足或编码器异常；
- 启动瞬间 `SAT` 闪一下是正常的（正在加速）。

### 9.9 复位

`PID_Reset()` 清零全部内部状态：积分、上一次测量值、滤波后的变化率与观测量。

调用时机：

| 时机 | 原因 |
|---|---|
| 驱动未使能时每个周期 | 保证再次使能时从零开始 |
| `START` / `RESET` 命令 | 用户主动复位 |
| 保护触发停机时 | 避免带着故障前的积分值重启 |
| 开环/闭环切换时 | 两种模式的输出含义不同，不能带着历史 |

> **不复位会怎样**：停机时若保留积分值，重新使能后控制器会先吐出那个历史值，
> 表现为"一上电就窜一下"。

### 9.10 参数整定方法

**参数作用速查**

| 参数 | 增大它 | 过大的后果 | 过小的后果 |
|---|---|---|---|
| `Kp` | 响应变快，静差变小 | 振荡、超调、噪声放大 | 响应迟缓、静差大 |
| `Ki` | 静差消除变快 | 超调、低频振荡 | 静差长时间不消 |
| `Kd` | 阻尼增强，抑制超调 | 噪声放大、电机抖动发热 | 阻尼不足、易超调 |

**本项目推荐的三步试凑法**

```
第 1 步：先找到"多少占空比对应多少转速"（开环标定）
    OPEN → DUTY 800 → 读 OLED/曲线上的实际转速
    例：800 counts → 240 RPM，说明 1 count ≈ 0.3 RPM，
        想跑 1000 RPM 大约需要 3300 counts

第 2 步：只加 P
    CLOSE → KI 0 → KD 0 → 1000
    Kp 从 0.5 开始：0.5 → 1 → 2 → 4 → 8 …
    目标：响应快、接近目标（允许静差）、不出现等幅或发散振荡
    本项目 Kp = 2.0 时，500 RPM 阶跃的 P 项贡献 1000 counts（约 24% 占空比）

第 3 步：加 I 消静差
    Ki 从小往大试：1 → 5 → 10 → 20 …
    目标：静差归零；若出现"冲过头再摆回来"，说明 I 太大，退一档
    仍超调就启用积分分离：SEP 60

第 4 步（可选）：加 D
    KD 从 0.01 起试；编码器噪声大时同时降 DFILT（如 DFILT 0.2）
    转速环通常 KD = 0 也能工作，本项目给了很小的 0.02 作为起始阻尼

第 5 步：固化
    SAVE 打印当前参数 → 填回 app.h 的 APP_DEFAULT_*
```

**关于"为什么 Kp 是 2.0 这个数量级"**

`Kp` 的量纲是 `counts / RPM`，满量程 4199 counts。
若希望"100 RPM 的误差就贡献约 25% 占空比"，则

```
    Kp = 0.25 × 4199 / 100 ≈ 10.5
```

若希望更保守（100 RPM 误差只贡献 5% 占空比）：

```
    Kp = 0.05 × 4199 / 100 ≈ 2.1     ← 本项目取值
```

也就是说 `Kp = 2.0` 属于**偏保守**的起步值，配合 `Ki = 10` 消除静差，
结果是"响应约 1.7 s、几乎无超调"，适合第一次上电，不适合追求快速性。

### 9.11 默认参数的来源

默认参数不是拍脑袋定的，而是先用一阶电机模型扫参数得到的：

**被控对象模型**

```
    dv/dt = ( K_plant · u_eff − v ) / τ

    K_plant = 1200 RPM / 4199 counts = 0.2858 RPM/count   （满占空比 1200 RPM）
    τ       = 80 ms                                        （机电时间常数）
    u_eff   = u − 120 counts（死区，约 2.9% 占空比）
```

**扫描结果节选**（1000 RPM 阶跃，指标 = 稳定时间 / 超调）

| Kp \ Ki | 1.0 | 2.0 | 5.0 | 10 | 20 | 40 |
|---|---|---|---|---|---|---|
| 2.0 | 19.1s / 0% | 9.4s / 0% | 3.7s / 0% | **1.8s / 0%** | 0.8s / 0% | 0.3s / 1% |
| 5.0 | 25.9s / 0% | 12.9s / 0% | 5.1s / 0% | 2.5s / 0% | 1.2s / 0% | 0.6s / 0% |
| 10.0 | 35.1s / 0% | 17.5s / 0% | 7.0s / 0% | 3.5s / 0% | 1.8s / 0% | 0.9s / 0% |

可以看出：

- **Ki 主导静差消除速度**（一阶对象没有超调风险，所以可以把 Ki 放得较大）；
- **Kp 增大反而变慢** —— 因为 Kp 大时 P 项提前顶到饱和，积分反而更慢地补足；
- 最终选择 `Kp = 2.0 / Ki = 10 / Kd = 0.02`：**1.74 s 稳定、超调 0%**，
  属于"慢但绝对安全"的起步参数。

> 真实电机有时间延迟、齿槽脉动和量化噪声，模型里没有，所以实机参数通常需要
> 比仿真值再小一点更稳。这套值的定位是"上电一定不会振荡"，而不是"性能最优"。

### 9.12 PID 模块接口

```c
/* 初始化：整定参数 + 两个限幅 + 积分分离阈值 */
void PID_Init(PID_t *pid, float kp, float ki, float kd,
              float i_limit, float o_limit, float sep_zone);

/* 在线修改整定参数（不清积分状态） */
void PID_SetTunings(PID_t *pid, float kp, float ki, float kd);

/* 设置微分低通系数 α ∈ (0,1]，传 0 或 >1 会被夹到 1（不滤波） */
void PID_SetDerivativeFilter(PID_t *pid, float alpha);

/* 计算一次输出，dt 单位秒 */
float PID_Compute(PID_t *pid, float target, float measure, float dt);

/* 复位积分、微分与全部观测量 */
void PID_Reset(PID_t *pid);
```

`PID_t` 结构体把**整定参数**、**限幅参数**、**内部状态**、**观测量**分开存放：

```c
typedef struct {
  /* 整定参数 */   float Kp, Ki, Kd;
  /* 限幅与非线性 */ float integral_limit, output_limit, sep_zone, d_lpf_alpha;
  /* 内部状态 */   float integral, last_measure, d_filtered;
  /* 观测量 */     float err, p_term, i_term, d_term, out;
                   uint8_t saturated;
} PID_t;
```

把 `p_term` / `i_term` / `d_term` / `saturated` 单独暴露出来，
是为了在线调试时能直接看"到底是哪一项在起作用"——
调参时最常见的困惑就是"输出打满了，是不足还是积分没跟上"，看这三项一目了然。

## 10. 保护与故障处理

### 10.1 两级保护

上电默认 `APP_AUTO_START = 1`（即上电就以 500 RPM 闭环运行），
在反馈通路尚未验证的情况下必须有兜底：

| 保护 | 触发条件（持续 `APP_FAULT_MS = 500 ms`） | 锁定信息 | 典型原因 |
|---|---|---|---|
| **FAULT OVERSPEED** | `\|实际\| > 3000 RPM`<br>或 `\|实际\| > \|目标\|×2 + 200`（目标 ≥ 200 时） | `FAULT OVERSPEED` | 编码器极性接反导致正反馈；参数严重不当 |
| **FAULT NO FEEDBACK** | 输出 ≥ 90% 满量程 **且** `\|实际\| < 50 RPM` | `FAULT NO FEEDBACK` | 编码器无信号；电机没供电；堵转 |

**为什么过速用"相对判据"而不是只看绝对值**

绝对值判据（`|实际| > 3000`）有两个问题：

1. 电机满速只有 1200 RPM 时，正反馈飙到顶也到不了 3000，保护不触发；
2. 阈值定低又会与正常的反向过程冲突（反向时实际短暂与目标反号）。

所以主判据改成 **"实际是否远超目标"**：`|实际| > 2×|目标| + 200`。

```
  正常反向：目标 +800 → −800
      反向过程中 |实际| 最多 800，而阈值 = 2×800+200 = 1800
      800 < 1800 → 不触发                                        ✅

  正反馈失控：目标 +500，编码器接反
      PID 看到 e = 500 − (负值) 越来越大 → 输出顶到 4199
      实际转速真实值一路升到 1200（电机满速），反馈读数约 −1200
      |−1200| = 1200 > 2×500+200 = 1200 → 触发                    ✅

  目标很小时（< 200 RPM）：
      不启用相对判据（避免刹停、微调时误报），只保留 3000 RPM 绝对上限  ✅
```

### 10.2 故障状态机

```
                       ┌──────────┐
        上电 ──────────►│  正常    │◄──────── START / RESET / TARGET
        (APP_AUTO_START)│ ENABLE=1 │           (App_ClearFault)
                       └────┬─────┘
                            │ 保护条件持续 500 ms
                            ▼
                       ┌──────────┐
                       │  锁定    │  s_fault = 1
                       │ ENABLE=0 │  Motor_Stop()
                       │ OLED:FLT │  写 s_msg + 串口文本
                       └────┬─────┘
                            │ 每个控制周期都 Motor_Stop()，直到被解除
                            ▼
                     发送 START / RESET / 新目标值
```

锁定后：

- `s_enabled = 0`，`Motor_Stop()`，`PID_Reset()`；
- `s_fault = 1`，`App_ControlStep()` 每个周期都直接停机并返回；
- OLED 状态位显示 `FLT`，第 56 行显示故障原因；
- 串口（若文本回显打开）打印原因文本。

### 10.3 通信超时保护（可选）

`SAFE <ms>` 可开启：超过设定时间没收到任何命令就停机。
**默认关闭**，因为典型用法是"设一次目标然后盯着波形看"，
自动停机反而会干扰观察。

```c
if ((s_safe_ms > 0u) && (s_enabled != 0u) &&
    (HAL_GetTick() - VOFA_GetLastRxTick()) > s_safe_ms) { ... 停机 ... }
```

## 11. 并发模型与数据一致性

系统只有两个上下文：**SysTick 中断**（控制环）和**主循环**（命令/上报/显示），
另有 USART1 中断独立收发。没有 RTOS，因此并发问题靠"**单一写者**"原则解决。

### 11.1 变量所有权

| 变量 | 写者 | 读者 | 保护方式 |
|---|---|---|---|
| `s_speed_rpm` | SysTick ISR | 主循环 | 32 位对齐读写，天然原子 |
| `s_err` | SysTick ISR | 主循环 | 同上 |
| `s_target_rpm` | 主循环 | SysTick ISR | 同上 |
| `s_pid.Kp/Ki/Kd` | 主循环 | SysTick ISR | 同上 |
| `s_pid.integral` 等内部状态 | **仅 SysTick ISR** | 主循环（只读显示） | 单写者，无需保护 |
| `s_ring` / `s_head` | USART1 ISR | 主循环 | SPSC 环形缓冲 |
| `s_txring` / `s_tx_tail` | 主循环 | USART1 ISR | SPSC + PRIMASK 临界区 |
| `s_ms` / `s_tele_due` / `s_oled_due` | SysTick ISR | 主循环 | 单字节标志，天然原子 |

### 11.2 为什么不需要关中断

Cortex-M4 上**对齐的 32 位（float / uint32）读写是单条指令**，是不可分割的。
主循环写 `s_pid.Kp` 的同时中断读它，最坏情况是"读到旧值"或"读到新值"，
绝不会读到半个浮点数的位组合。对 PID 来说，一个周期用旧参数、下一周期用新参数
完全无副作用。

唯一需要显式临界区的是 6.4 节讲的 TX 环形缓冲"写入 + 使能中断"——
那里不是数据竞争，而是**中断使能位的竞态**。

### 11.3 中断优先级

| 中断 | 抢占优先级 | 说明 |
|---|---|---|
| USART1_IRQn | 5 | 收发各搬一个字节，执行时间 ~1 µs |
| SysTick_IRQn | 15（最低） | 控制环，每 10 ms 一次 |

优先级分组为 `NVIC_PRIORITYGROUP_4`（4 位抢占优先级，0 位子优先级），
由 `HAL_Init()` 设置。

USART1 优先级高于 SysTick：串口是硬实时的（数据不取走就丢），
而控制环晚几微秒毫无影响。串口中断每搬一个字节只花约 1 µs，
而字节间隔是 86.8 µs（115200 baud 下 10 bit/字节），
即使在满带宽情况下中断密度也只有约 11.5 kHz，
对 10 ms 控制周期的抖动贡献可以忽略。

### 11.4 时间预算

| 任务 | 频率 | 单次耗时 | 占用 |
|---|---|---|---|
| 控制环（中断） | 100 Hz | ~5 µs（含 FPU 浮点） | < 0.1% |
| USART1 收发中断 | 2 kHz 稳态 / 11.5 kHz 满带宽 | ~1 µs | 0.2% ~ 1.2% |
| VOFA 组帧（主循环） | 100 Hz | ~2 µs | < 0.1% |
| OLED 全屏刷新（主循环） | 10 Hz | **~25 ms** | **~25%** |

> USART1 中断频率 = 发送字节率。稳态下 20 B × 100 Hz = 2 000 次/秒；
> 只有在环形缓冲长期满载、链路跑满带宽时才达到 11 520 次/秒。

主循环的最大占用来自 OLED 的 I2C 传输，但因为：

- 控制环在中断里，不受影响；
- 数据上报走中断环形缓冲，不受影响；

所以这 25% 只影响"命令响应延迟"，而命令字节仍在 256 B RX 环形缓冲里排队。
若要进一步降低，可把 `APP_OLED_PERIOD_MS` 调到 200（降到 12.5%）。

## 12. 时基与优先级

### 12.1 时钟树

```
  HSE 8 MHz
     │  ÷ PLLM = 8
     ▼
  1 MHz ──(× PLLN = 336)──► 336 MHz ──(÷ PLLP = 2)──► 168 MHz SYSCLK
                                        └─(÷ PLLQ = 4)──► 84 MHz（USB/SDIO 用）

  SYSCLK 168 MHz
     ├─ AHB  ÷1  ──► HCLK 168 MHz
     │                ├─ APB1 ÷4 ──► PCLK1  42 MHz  ──► 定时器时钟 84 MHz  (TIM2/TIM3..)
     │                └─ APB2 ÷2 ──► PCLK2  84 MHz  ──► 定时器时钟 168 MHz (TIM1/TIM8)
     └─ SysTick 时钟源 = HCLK = 168 MHz
          HAL_InitTick() → SysTick_Config(168 000 000 / 1000) = 168 000
          → 1 ms 中断，优先级 TICK_INT_PRIORITY = 15（最低）
```

> SysTick 走的是**处理器时钟 HCLK**（CMSIS `SysTick_Config()` 置 `CTRL.CLKSOURCE`），
> 不是 HCLK/8。所以重装载值就是 `SystemCoreClock / 1000`。

| 时钟 | 频率 | 用到的外设 |
|---|---|---|
| SYSCLK | 168 MHz | 内核、SysTick |
| HCLK | 168 MHz | DMA、Flash（5 等待周期） |
| PCLK1 | 42 MHz | I2C1、USART2.. |
| PCLK1 定时器 | 84 MHz | TIM2（PWM，→ 20 kHz） |
| PCLK2 | 84 MHz | USART1（→ 115200） |
| PCLK2 定时器 | 168 MHz | TIM1（编码器接口，无分频） |

**关键换算**

```
   USART1 波特率：BRR = 84 MHz / 115200 = 729  →  实际 115 226 baud（误差 0.02%）
   TIM2 PWM     ：84 MHz / (0+1) / (4199+1) = 20 kHz
   TIM1 编码器  ：168 MHz 计数，用于 16 位正交解码（不涉及频率）
```

### 12.2 定时器配置一览

| 定时器 | 模式 | Prescaler | Period | 频率 / 用途 |
|---|---|---|---|---|
| TIM1 | 正交编码器接口 TI12 | 0 | 65535 | 16 位计数，4 倍频，每 10 ms 读一次 |
| TIM2 | PWM 输出 CH1 | 0 | 4199 | 20 kHz，占空比分辨率 4200 级 |

## 13. 数值分析与设计依据

### 13.1 速度测量分辨率的取舍

M 法测速的分辨率与窗口长度成反比：

```
   分辨率 [RPM] = 60 / ( N_rev × T ) = 60 / (1600 × T)
       T = 10 ms → 3.75 RPM
       T = 20 ms → 1.875 RPM
       T = 50 ms → 0.75 RPM
```

窗口越长分辨率越高，但**延迟也越大**，而延迟直接吃掉控制带宽。
本项目取 10 ms 与 PID 周期对齐：

- 分辨率 3.75 RPM：在 500 RPM 工作点上相当于 **0.75% 的量化噪声**，可接受；
- 延迟 5 ms（窗口均值）+ 15 ms（EMA 滤波）≈ **20 ms**。

低速段（< 50 RPM）时 3.75 RPM 已经相当于 7.5% 的误差，控制品质会明显下降 ——
这是 M 法的固有限制，要改善需改用 **M/T 法**（低速时测脉冲间隔）。

### 13.2 采样周期与量化噪声的权衡

采样周期 T 越小，量化噪声（每周期 ±1 个计数）被放大得越厉害：

```
   噪声转速 = 3.75 RPM/计数 ÷ T
       T = 10 ms → 375 RPM/s 的变化率噪声
```

这个 375 RPM/s 就是 D 项看到的噪声底，`Kd = 0.02` 时是 7.5 counts，
`Kd = 1.0` 时是 375 counts —— **这就是必须给 D 项加低通的原因**。

### 13.3 反馈延迟预算

| 环节 | 延迟 | 来源 |
|---|---|---|
| 编码器采样窗口 | ≈ 5 ms | 10 ms 窗口取平均 |
| EMA 测速滤波 | ≈ 15 ms | `(1−α)/α × T`，α=0.4 |
| 控制周期 | ≈ 5 ms | 采样到执行的半周期延迟 |
| **合计** | **≈ 25 ms** | |

被控对象机电时间常数 τ ≈ 80 ms，则 **延迟/时间常数 ≈ 0.3**。
经验上，这个比值决定了闭环能取到的最大比例增益：

- 比值 < 0.1：可以做得很快；
- 比值 ≈ 0.3（本项目）：Kp 偏保守，靠积分补足；
- 比值 > 1：基本只能做很慢的控制。

要降低延迟：减小 `ENCODER_FILTER_ALPHA` 的滤波强度（提高 α）、缩短采样窗口，
或提高控制频率。三者都要以噪声增大为代价。

### 13.4 位置式 vs 增量式

本项目用**位置式** PID，而不用增量式：

| | 位置式（本实现） | 增量式 |
|---|---|---|
| 输出 | 直接是控制量 | 控制量的增量 |
| 积分 | 显式累加，需要抗饱和 | 隐含在累加里，天然抗饱和 |
| 输出含义 | **就是占空比**，可直接限幅 | 是 Δu，限幅含义不直观 |
| 切换/复位 | 需要显式 Reset | 状态少 |
| 调试 | P/I/D 三项可分别观测 | 难以分离观测 |

对于"输出就是 PWM 占空比"这种场景，位置式更直观，也更容易做限幅和分项观测。

### 13.5 浮点 vs 定点

Cortex-M4F 有单精度硬件浮点单元（FPU），`-mfpu=fpv4-sp-d16 -mfloat-abi=hard`。
一次 `PID_Compute()` 约 30 次浮点运算，在 168 MHz 下不足 1 µs，
相对于 10 ms 控制周期完全可以忽略。因此直接用 `float`，
换取代码清晰、参数可以直接用物理量表示。

> 注意：`double` 在 M4F 上是**软件模拟**，比 `float` 慢几十倍。
> 本项目所有实时路径一律使用 `float`，后缀 `f` 从不省略。

## 附录 B：公式速查

```
【测速】
  每转计数      N_rev = 线数 × 倍频 × 减速比 = 400 × 4 × 1 = 1600
  RPM           n = ΔN × 60 / (N_rev × T) ,  T = 10 ms
  换算系数      RPM/计数 = 60 / (1600 × 0.01) = 3.75
  最大可测      |ΔN| < 32768  →  122 876 RPM
  测速滤波      n_f[k] = n_f[k-1] + α(n_raw[k] − n_f[k-1]),  α = 0.40
  滤波带宽      f_c ≈ 8.3 Hz（α=0.40, T=10 ms）
  滤波群延迟    ≈ (1−α)/α × T ≈ 15 ms

【PID】
  误差          e[k] = r[k] − y[k]
  微分（先行）  ẏ[k] = (y[k] − y[k−1]) / T
  微分低通      ẏ_f[k] = ẏ_f[k−1] + α(ẏ[k] − ẏ_f[k−1]),  α = 0.30
  积分          I[k] = clamp(I[k−1] + Ki·e[k]·T, ±I_lim)
  输出          u = Kp·e + I − Kd·ẏ_f
  抗饱和        若 u 饱和且 e 同向 → I[k] = I[k−1]，重算 u
  限幅          u = clamp(u, ±U_lim),  U_lim = 4199

【量纲】
  Kp [counts/RPM]     Ki [counts/(RPM·s)]     Kd [counts·s/RPM]
  e  [RPM]            y  [RPM]                u [counts, ±4199]

【PWM】
  占空比        D = CCR1 / (ARR+1) = CCR1 / 4200
  PWM 频率      f = 84 MHz / (PSC+1) / (ARR+1) = 84 MHz / 4200 = 20 kHz

【通信】
  JustFloat 帧  4 × float(小端) + 00 00 80 7F = 20 字节
  帧尾含义      0x7F800000 = +Inf
  带宽          20 B × 100 Hz = 2 000 B/s = 115200 链路的 17.4%
  TX 环容量     512 B ≈ 25 帧≈ 250 ms 数据（100 Hz 时）

【时基】
  控制环        SysTick 1 ms → 每 10 ms 执行一次（中断内）
  上报          每 10 ms 置标志 → 主循环执行
  显示          每 100 ms 置标志 → 主循环执行
```

## 附录 C：故障排查

### C.1 现象 → 原因对照

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| **串口全是 `00/1C/E0/FC`，看不到 `00 00 80 7F`** | 晶振与 `HSE_VALUE` 不符（25 MHz 配置 + 8 MHz 实物 = 波特率低 3.125 倍） | 串口工具改 **36864** 波特率验证；根治改 `HSE_VALUE` 与 `PLLM` |
| VOFA+ 无波形 | 通道数不是 4 / 数据引擎选错 / 波特率不符 | 数据引擎 JustFloat，通道数 **4**，115200 |
| 接收区乱码 | JustFloat 是二进制 | 接收区勾选十六进制显示 |
| 发 `HELP`/`SAVE` 无反应 | JustFloat 下文本默认静音 | 先发 `TEXT 1` |
| 文本一出现波形就跳 | ASCII 混进了二进制流 | 发 `TEXT 0` |
| **电机完全不动** | 未使能；或功率通路问题 | 发 `DUTY 800` 开环测试：**开环不转 → 硬件问题**；开环能转 → 反馈问题 |
| 上电转一下停，显示 `FAULT NO FEEDBACK` | 编码器无信号 | 查 A/B 相接 PE9/PE11、编码器供电、`ENCODER_GEAR_RATIO` |
| 一上电冲高后停，显示 `FAULT OVERSPEED` | 编码器极性接反（正反馈） | `ENCODER_DIR_INVERT` 改 `1`，或对调 A/B 相 |
| 转速为负 / 符号相反 | 同上 | 同上 |
| 转速是实际值的 30 倍 | 减速比没填 | 改 `ENCODER_GEAR_RATIO` |
| 低速抖动、分辨率粗 | M 法固有：3.75 RPM/计数 | 减小 `ENCODER_FILTER_ALPHA`，或延长采样窗口 |
| 电机啸叫 | PWM 频率异常（时钟错） | 确认 `PLLM` / `HSE_VALUE`，应为 20 kHz |
| 输出长期 `SAT` 但转速上不去 | 功率不足 / 堵转 / 编码器异常 | 查电源电压、机械负载；看 `FAULT` 是否触发 |
| OLED 花屏 | I2C 速率/接线 | `i2c.c` 的 `ClockSpeed` 改回 100000 |
| OLED 只显示一半 | 0.91 寸 128×32 屏 | `OLED_HEIGHT` 改 32 |
| OLED 整体偏移 2 列 | 1.3 寸 SH1106 | `OLED_CTRL_SH1106` 改 1 |
| 发数字 ch0 不变 | 命令没被解析 | 发 `TEXT 1`，收不到 `TEXT REPLY ON` 即为串口链路问题 |

### C.2 分层排查法（推荐顺序）

```
① 串口链路通不通？
     发 TEXT 1 → 应回 "TEXT REPLY ON"
     ↓ 不通 → 波特率 / 晶振 / TX-RX 交叉接线

② 波形对不对？
     数据引擎 JustFloat，通道数 4 → 应见 4 条曲线
     ↓ 不对 → 是上位机配置问题

③ 功率通路通不通？（绕过编码器和 PID）
     DUTY 800 → 电机应以约 1/5 满速转
     ↓ 不转 → TB6612 接线 / VM 供电 / STBY / PWM 引脚

④ 反馈通路对不对？（仍然开环）
     DUTY 800 → 看 ch1 转速是否与转向、幅值一致
     ↓ ch1 恒 0 → 编码器无信号
     ↓ 符号相反 → ENCODER_DIR_INVERT

⑤ 闭环
     CLOSE → 500 → ch1 应稳定在 500
     ↓ 振荡 → 按 9.10 节重新整定
```

**第 ③ 步是整个排查的关键分水岭**：`DUTY` 命令走开环，
不经过编码器也不经过 PID，所以"它不动"就一定不是算法问题。
